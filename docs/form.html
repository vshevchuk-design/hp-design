Form

tokens/components/field.tokens.json + form.tokens.json · generated — Field wraps any control with its label, description and error; Form stacks Fields, splits them into sections and validates on Submit.

FieldControl, then a description (4px below, body-sm · text.secondary), then the error. Every later field (Combobox, NumberField, MultiSelect…) sits in this same wrapper.
LabelInput and Select keep their floating label — resting, the placeholder shows it; it floats to 12px on focus or once there's a value. A label above (heading-sm, 8px) only for controls without one: DatePicker, a checkbox or radio group, Switch, Input sm.
No Label componentRadix/shadcn's Label is a styled <label>. Here it's built in where labels live: the Field's label above, Input/Select's floating label, the text beside a Checkbox / Radio. Each wires for/id itself, and there are exactly two looks (heading-sm above a field, body-base beside a check) — no weight or tone props to pick per screen.
ErrorUnder the description — it stays, since it usually explains the rule. text.danger with the error icon (never colour alone), the control takes Input's border.danger, the label stays text.default. aria-invalid on the control, the message wired through aria-describedby.
WhenOn Submit — nothing is red before the first attempt. After it, each field re-checks as it's corrected, so the error clears the moment it's fixed. Submit with errors moves focus to the first invalid field.
RequiredThe norm, not marked. The rare optional field says "(optional)" — fewer marks than asterisks on every field.
LayoutOne column, max 480px (Dialog sm's width). 24px between fields, 40px between sections (<fieldset> + <legend>, heading-md). Actions under the last field, Primary first.
